# PickFinder phone-only hosted runner (ESP-062/063)

The public workflow is `.github/workflows/pickfinder-premium-hosted.yml`. It runs only on public main, with no self-hosted hardware. Raw data remains in the verified private archive. Do not add secrets as variables, commit them, or send them in chat. Owner reports specific automation permission; independent written scope and login support remain unverified.

1. In public repository Settings > Secrets and variables > Actions, confirm `PRIVATE_RESEARCH_REPO_TOKEN` has read/write contents access to the private archive. Add repository secrets `PICKFINDER_EMAIL` and `PICKFINDER_PASSWORD` only if you use ordinary PickFinder email/password login and have authorization for automated login. Alternatively use a provider-authorized `PICKFINDER_STORAGE_STATE` JSON secret if available; it takes precedence. No bypass for MFA, Google-only login, CAPTCHA or provider denial. Do not publish raw data.
2. Set Actions variable `PICKFINDER_AUTOMATION_AUTHORIZED=1`. Leave `PICKFINDER_HOSTED_AUTH_VERIFIED`, `PICKFINDER_HOSTED_CAPTURE_VERIFIED`, and `PICKFINDER_SCHEDULE_ENABLED` unset until verified.
3. Run `audit_pilot` to independently report historical unresolved counts with no provider access. Run `probe_now` from Actions to verify the normal login in a fresh cloud browser; repeat in a separate run. Only after actual success set `PICKFINDER_HOSTED_AUTH_VERIFIED=1`.
4. Dispatch `capture_0600` or `capture_0900` in the corresponding Pacific hour; require real remote archive evidence, separate counts and no guessed missing rows. Only after verification set `PICKFINDER_HOSTED_CAPTURE_VERIFIED=1` and `PICKFINDER_SCHEDULE_ENABLED=1`. Schedule is 06:07 and 09:07 Pacific. If login fails, stop and obtain a provider-supported authentication path. No automatic retry or credential logging.

Old rows lack underlying display evidence and cannot be reconstructed. Capture new evidence; do not backdate. Models remain locked.
